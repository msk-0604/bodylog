## 3. 取り込む値と扱い

| BODYLOG の列     | 成分識別子（INFOODS） | 成分表の項目       |
| ---------------- | --------------------- | ------------------ |
| `energy_kcal`    | `ENERC_KCAL`          | エネルギー（kcal） |
| `protein_g`      | `PROT-`               | たんぱく質         |
| `fat_g`          | `FAT-`                | 脂質               |
| `carbohydrate_g` | `CHOCDF-`             | 炭水化物           |

- 値はすべて**可食部100gあたり**。
- 「たんぱく質」「脂質」「炭水化物」は、食品の栄養成分表示で一般的な項目を採用（アミノ酸組成によるたんぱく質・脂肪酸のトリアシルグリセロール当量・利用可能炭水化物は採用しない）。採用方針を変える場合は MVP_SPEC.md §5 と合わせて更新する。
- 糖質は扱わない（炭水化物と混同しない）。

| 成分表の表記  | 取り込み値   | `value_flags`    | アプリでの扱い                          |
| ------------- | ------------ | ---------------- | --------------------------------------- |
| 数値          | その値       | なし             | 通常                                    |
| `-`（未測定） | `NULL`       | `missing`        | 「不明」表示、合計に含めず注記          |
| `Tr`（微量）  | 0            | `trace`          | 0として計算、「微量（Tr）」と表示       |
| `(Tr)`        | 0            | `trace`          | 同上                                    |
| `(0)`         | 0            | `zero_estimated` | 推定値として表示                        |
| `(数値)`      | その値       | `estimated`      | 推定値として表示                        |
| 上記以外      | 取り込まない | —                | レポートの `skipped` に出力し、手動確認 |

- 食品ID：食品番号から決定的に生成（UUID v5 形式）。版を更新しても同じ食品は同じIDのままなので、お気に入り・テンプレートの参照が切れない。
- 新しい版に存在しない食品は `is_active = false`（検索に出なくなるが、過去の記録は記録時点の栄養値スナップショットを保持しているため変わらない）。
- 個数・パック等の換算重量（`food_serving_units`）は成分表に含まれないため取り込まない。根拠のある換算データを入手するまで、分量はg入力（＋マイ食品の「1食あたり」）で対応する。

## 4. 更新手順

1. 文部科学省サイトから最新の「本表」Excel（全食品群を含むもの）をダウンロードし、利用条件と正誤表を確認する（§2）。
2. 取り込み用SQLを生成する（Node.js 22 以上）：
   ```bash
   npm run foods:import -- --input ~/Downloads/<本表>.xlsx --version "八訂増補2023" \
     --out food_master.sql --report food_master_report.json
   # 本表が先頭シートでない場合は --sheet "<シート名>"
   ```
3. `food_master_report.json` を確認する：
   - `foods`（件数）が公表の食品数と一致するか
   - `skipped` に想定外の表記がないか（あればパーサー `scripts/foods/mext.ts` を更新）
   - いくつかの食品を成分表と目視照合する（例：穀類・卵類・調味料から各数件）
4. ステージング用のSupabaseに適用し、アプリで検索・計算を確認する：
   ```bash
   psql "$STAGING_DB_URL" -v ON_ERROR_STOP=1 -f food_master.sql
   ```
5. 本番に適用する（**本番データの変更はプロジェクトオーナーの承認後**）。SQLは冪等なので再実行しても重複しない。
6. `docs/TASKS.md` の検証ログと本ドキュメントの「確認結果」を更新する。

接続文字列（`*_DB_URL`）や service_role キーは開発者の端末・CIのシークレットでのみ扱い、アプリやリポジトリに含めない。

## 5. 検証状況

- パーサー：架空の行データで単体テスト済み（`scripts/foods/__tests__/mext.test.ts`）。exceljs で作成したダミーxlsxからCLIでSQL生成まで確認済み。
- 生成SQL：ローカルPostgreSQLに2回適用し、冪等性・検索RPC・NULL保持をテスト済み（`supabase/local-tests/30_food_import.sql`）。
- **文部科学省の実ファイルでの取り込みは未実施**（ネットワーク制限のため）。成分識別子の行の表記などが想定と異なる場合、スクリプトは推測せずエラーで停止する。
