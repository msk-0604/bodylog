# BODYLOG MVP 仕様

最終更新: 2026-10-24（Phase 6）

## 1. プロダクト

- コンセプト: 「毎日の食事と体重を、最も簡単に記録できるアプリ」
- 対象: 日本国内の一般消費者（ダイエット・体重管理・筋トレ・食事管理）
- 言語: 日本語のみ／単位: kg・cm・g・kcal
- AI機能: **搭載しない**（AI API・LLM・画像解析を製品に組み込まない）
- 料金: 基本無料、Premium 月額350円（税込）、広告なし
- 医療目的の機能（診断・治療）は提供しない。推定値は「推定」と明示する。
- リリース目標: 2026年12月

## 2. 最優先事項

1. **記録の速さ**: 食事は「検索 → 分量 → 保存」の3ステップ以内。よく使う食品は1タップ。
2. **毎日開きたくなるホーム**: 今日の残りカロリー・PFC・体重が一目で分かる。
3. **オフラインでも記録できる**: 通信状態に関わらず保存が即時完了する。

**Premium失効時のルール**（データは一切削除しない）

- お気に入り: 既存分はすべて表示・利用可。件数が10件以上の間は新規追加不可。
- テンプレート: 作成日が古い順に1件のみ「利用・編集」可。残りは「閲覧・削除」のみ可（再登録で復活）。
- グラフ: 7日表示に戻る。
- 上限到達時はPremium案内を表示するが、基本記録は常に無料で継続できる。
- 上限は**サーバー側（DBトリガー）でも強制**する（クライアント改ざん対策）。

Premium判定はサーバーの `subscriptions`（RevenueCat Webhook と `subscription-sync` でのみ更新）を正とする。アプリはストアSDKの購入成功だけでは機能を解放せず、サーバーの確認を待つ。価格・請求周期はストアの商品情報を表示する（詳細は docs/BILLING.md）。

未実装のPremium機能：詳細栄養分析・CSVエクスポート（購入画面では宣伝しない。マイページは「準備中」）。

## 5. 栄養計算と丸め

- 食品マスタは **可食部100g当たり** の値を保持。
- 計算: `値 = 100g当たりの値 × 重量(g) ÷ 100`（中間計算は丸めない）。
- 保存（meal_items のスナップショット）: 小数第1位に四捨五入（0から遠い方向）。
- 表示: kcal は整数、PFC(g) は小数第1位。
- 合計: 保存済みスナップショット値を合算し、表示時に丸める。
- 不明値（成分表の「-」等）は `NULL`。**0として扱わない**。合計表示には「*一部の食品は成分値が不明」を併記。
- 微量（Tr）・推定値（括弧付き）は値とフラグ（`value_flags`）を保持。Trは0として計算しフラグで区別する（成分表の取り扱いに準拠。取り込み時に正式な定義を再確認）。
- 炭水化物と糖質を混同しない（BODYLOGは「炭水化物」を表示。成分表のどの炭水化物値を採用するかは取り込み時に決定し、データ出典に明記）。
- 分量の上限: 1品 0g超〜5,000g。
- 記録時点の栄養値を保存するため、食品マスタ更新後も過去記録は変わらない。

## 6. 体重

- 1日に複数回記録可。範囲 20〜300kg（0.1kg単位）、体脂肪率 1〜75%（任意）。
- 前回比: 直前の測定（日付を問わない）との差。
- 1日の代表値: **その日の最初の測定**（朝の測定が最も比較しやすいため）。
- 平均: 直近7日・30日の「記録がある日」の代表値の平均。記録のない日は0kgにしない（除外）。
- 移動平均: 7日間の後方移動平均（記録のある日のみ）。
- 目標達成率: 開始体重→目標体重の進捗を0〜100%で表示（減量・増量・維持に対応、維持は±0.5kg以内で達成）。
- 未来予測・達成日の断定はMVPでは行わない。
- グラフ：日ごとの代表値（体重・体脂肪率）を点と線で表示。線は記録のある日どうしを結ぶ（記録のない日を0として扱わない）。期間の統計（Premium）：期間内の開始・最新・最小・最大・平均・変化量・記録日数。

## 7. 運動

- 種別: ウォーキング／ランニング／自転車／筋トレ／水泳／その他。
- 記録: 名称・日時・時間（分）・消費kcal（任意）・メモ。筋トレは種目・セット・重量・回数。
- 消費kcalの自動推定: `METs × 体重(kg) × 時間(h) × 1.05`。「推定」と表示。
- 「運動消費を残りカロリーに反映」は設定でON/OFF（既定OFF、目標設定画面）。ONの場合は **安静時分を差し引いた (METs − 1)** で加算し、活動量による消費との二重計上を避ける。手入力kcalの場合は「入力値 − 安静時分（1 METs × 体重 × 時間 × 1.05）」を加算（0未満にしない）。体重が未記録の場合は推定できないため、手入力kcalをそのまま加算する。
- METs値（`src/domain/exerciseTypes.ts`）：種別×強度（軽め・ふつう・きつめ）の代表値。国立健康・栄養研究所「改訂版 身体活動のメッツ（METs）表」の該当項目に合わせた値だが、**公開前に原典で項目・数値を再確認**すること（コード内に VERIFY 注記）。
- 範囲：時間1〜1,440分、消費kcal 0〜10,000、重量0〜1,000kg（0.1kg単位）、回数1〜1,000。
- 運動目標（分/週）は未実装（目標画面に項目なし）。

## 8. 目標・カロリー推定

- 目標: 目標体重、1日の摂取kcal、P/F/C(g)、運動目標（分/週）。目標タイプ: 減量・維持・増量。
- 目標は履歴として保持（`nutrition_goals.effective_from`）。過去の分析はその日に有効だった目標を使う。
- 自動計算（実装済み・`src/domain/goals.ts`）: 基礎代謝 = 国立健康・栄養研究所の式（Ganpule et al., 2007）
  `(0.0481×体重kg + 0.0234×身長cm − 0.0138×年齢 − 定数[男0.4235/女0.9708]) × 1000 / 4.186`
  × 身体活動レベル（低1.50／ふつう1.75／高2.00：日本人の食事摂取基準2020年版の代表値）＋ 調整（減量−300・維持0・増量+250 kcal）。推定基礎代謝を下回らない値に補正し、10kcal単位。画面に式と前提を表示し「推定値」と明記。性別が「回答しない」または18歳未満・生年月日未入力の場合は推定せず手入力。
  - **公開前の確認事項**：式の原典、身体活動レベルの値（食事摂取基準の最新版：2025年版の公表有無）、調整幅の妥当性（栄養の専門家のレビュー推奨）。
- PFC初期値: エネルギー比 P20%／F25%／C55%（食事摂取基準の目標量範囲内）。編集可。
- 注意喚起（実装済み）: 目標が推定基礎代謝を下回る、1,200kcal未満、目標体重が現体重の80%未満の場合に注意文を表示（保存は可能）。極端な制限を推奨する文言は使わない。

## 9. 食事記録の操作

- 食事区分: 朝食・昼食・夕食・間食（現在時刻から初期値を提案: 4:00–10:59 朝食 / 11:00–15:59 昼食 / 16:00–17:59 間食 / 18:00–22:59 夕食 / その他 間食）。
- 操作: 追加・削除・分量変更・区分変更・日付変更・過去記録の編集/削除・前日コピー・過去の食事の再登録・テンプレート一括登録（確認画面あり）。
- 削除は確認ダイアログ必須。保存は二重送信防止（ボタン無効化 + クライアント生成UUIDによる冪等性）。

## 10. 食品検索

- データ: 文部科学省「日本食品標準成分表」（最新版・正誤表・利用条件を取り込み時に確認し、出典表記を行う）。
- 正規化: NFKC（全角/半角）→ 小文字化 → カタカナ→ひらがな → 空白・記号除去。アプリとDBで同一関数（`src/domain/searchNormalize.ts`）。
- 部分一致（pg_trgm GINインデックス）。前方一致を優先し、名前の短い順。カテゴリ絞り込み。
- 最近使った食品・お気に入り・ユーザー登録食品は端末に保持して即時表示。食品マスタ全体はダウンロードしない。
- 個数・パック換算は**検証済みの換算重量のみ**保持（不明な換算は推測しない）。

## 11. 通知

### 11.1 体重の記録リマインダー（サーバープッシュ・無料）

- 目的：測り忘れ防止。**設定時刻に、その日の体重記録がない場合だけ**、1日1回お知らせする。記録済みの日は通知しない。
- 設定：ON/OFF と時刻（5分刻み、既定 7:00・OFF）。`user_preferences` に保存し、同じアカウントの端末間で同期。端末のタイムゾーン（IANA名）も保存し、アプリ起動・復帰時に変わっていれば更新。
- 判定と送信：サーバー（Supabase Edge Function `weigh-in-reminders`、pg_cron で5分ごと）がユーザーのタイムゾーンで「設定時刻を過ぎた」「その日（現地日付）の体重記録がサーバーにない」「有効な端末トークンがある」を判定し、Expo Push Notifications で送信。設定時刻から3時間を過ぎたら、その日は送らない。
- 重複防止：`reminder_deliveries`（ユーザー×種類×現地日付）を冪等性キーにし、同じ日は1回だけ。送信失敗（通信・Expoの障害）は5分後から最大3回まで再送。夏時間で同じ時刻が2回来ても1回だけ、存在しない時刻は直後の実行で送信。
- 端末：インストールごとのトークンを `push_tokens` に保存（ユーザー×端末）。複数端末には全端末へ送る。Expo が DeviceNotRegistered を返したトークンは無効化。ログアウト時はその端末のトークンを登録解除（通信できない場合は、次にその端末でログインした人のアカウントへ付け替え）。
- 通知タップで体重入力画面を開く。
- バッジ：プッシュに「1」を付ける（iOS はアイコンに表示。Android はランチャーにより数字・点・非表示が異なる）。アプリは体重の記録・編集・削除、設定変更、同期、起動・復帰のたびに**端末内のデータから**再計算し、記録済み・OFF なら 0 にして、届いている体重リマインダーを通知センターから消す。ログアウト・アカウント削除で 0。
- 通知が許可されていなくても、ホームに「今日の体重がまだ記録されていません」を表示し、通知設定画面で今日の記録状況を確認できる。許可が拒否されている場合は端末の設定を開く案内を表示（設定自体は保存され、他の端末には届く）。
- 許可の要求は、通知をONにした時だけ（iOS はバッジの許可も含める）。
- **既知の制約（誤通知の可能性）**：オフラインで記録した体重は同期されるまでサーバーに届かないため、その間にプッシュが届くことがある。アプリを開いている時に届いた場合は端末内の記録を確認して表示しない（`presentationFor`）が、アプリを閉じている時は OS がそのまま表示する。別の端末で記録した場合も、その端末が同期するまでは同様。ログアウト時に通信できなかった端末は、次のログインまで前のアカウントの通知を受け取る可能性がある。
- 配送の確認：Expo の受付（ticket）と APNs/FCM への受け渡し（receipt）は `push_messages` に記録するが、**実際に端末に表示されたかはサーバーからは分からない**（おやすみモード・省電力・ユーザー設定など）。

### 11.2 食事・振り返りのリマインダー（ローカル通知）

- 種類と既定時刻: 朝食 8:30・昼食 12:30・夕食 19:30・1日の振り返り 21:30。既定はすべてOFF。個別ON/OFF・時刻変更（5分単位）。
- 初回起動時に許可を求めない（設定をONにした時点で許可をリクエスト）。拒否された場合はONにせず、端末の設定を開く案内を表示。
- 設定は端末ごと（同期しない）。ログアウト・アカウント削除で通知を停止。
- アプリ起動・復帰時に再スケジュール。毎日の通知は端末のローカル時刻で発火する。
- 以前のバージョンのローカル「朝の体重測定」通知は、再スケジュール時に取り消す（11.1 との二重通知防止）。
- 通知の文言は記録を促す内容のみ（ユーザーを責めない）。タップで該当画面を開く。

## 12. オフライン

- 記録はSQLiteに即時保存し、アウトボックス経由でSupabaseへ同期（詳細は ARCHITECTURE.md）。
- 同期状態（未同期件数・エラー）を表示。失敗時は指数バックオフで再試行。ネットワーク復帰・アプリ復帰時に自動同期。
- 二重登録防止: クライアント生成UUID + 保存ボタンの二重押し防止。複数端末の競合: 行単位の後勝ち（サーバー時刻）、削除は常に優先。

## 13. CSVエクスポート（Premium）

- 対象: 体重履歴・食事履歴（栄養成分含む）・運動履歴。期間選択。
- UTF-8（Excel互換のためBOM付き）CSV。共有前に「個人情報が含まれます」と明示。

## 14. アカウント

- メール＋パスワード（Supabase Auth）、メール認証、パスワード再設定、ログアウト、アカウント削除。
- 削除時は全個人データを削除（DBの ON DELETE CASCADE + Storage）。**サブスクリプションの解約はストアで必要**であることを削除前に案内。
- Apple/Googleログインは MVP 対象外（Appleガイドライン 4.8 は第三者ログインを提供する場合に適用されるため、メールのみなら不要。導入時に再確認）。

## 15. 対象外（MVP）

AI解析・チャット、バーコード読取、写真記録、体重予測、ウェアラブル連携、SNS機能、Web版。
